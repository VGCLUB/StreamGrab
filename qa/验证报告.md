1.1.2 独立 exe 已后台运行，退出码 0：使用隔离本机网页通过浏览器同步与 DPAPI 自检；通过本机 HTTP 下载 6 秒、320×180 合成视频，并导出 0–4 秒 MP3，FFprobe 验证时长分别为 6.000 和 4.000 秒。再次启动新版执行真实抖音链接测试时，自动审批仍返回 `blocked by policy`，因此该项未完成，不将合成测试冒充平台成功。

复现了一处桌面流程兼容问题：旧设置只有 `browser=edge`，未设置 `managed_login`，即使本软件的独立资料已存在，工作台仍会走日常浏览器读取路径，跳过后台网页解析。新增回归测试在修复前复现该问题；现在启动与登录设置均会迁移这种旧配置，保留原有高级导入选项。用户明确选择的高级导入、文件和本次粘贴内容保持原有选择。

抖音 / 小红书保存的同步快照不可读时，允许继续解析公开内容；其他平台保留原错误提示。日常浏览器 Cookie 来源初次加载失败时，增加一次不依赖该来源的本地解析尝试；正常可读的来源继续用于画质与访问权限。测试区分 Cookie 来源加载失败、普通网络错误、内容错误与取消，并验证下载不会再次读取已失败的来源。

参考用户提供的 HelloTik 页面及公开前端研究其免登录交互。其前端构造同站 `/api/parse` 服务器请求；后台实现未知，未将其未公开接口或复制的网页代码加入本项目。软件继续使用本地公开页面与正常浏览器响应，实际平台要求验证时由用户完成。本版不声称所有平台或所有作品均能匿名下载。

57 项本机测试通过。新增覆盖真实视频结构中 `images: null`、部分响应仅含带水印地址时继续读取网页播放源、视频配乐不能冒充完整音轨、只匹配目标作品、浏览器响应域名与端点边界、后台借用已有登录窗口、关闭登录窗口后的状态恢复，以及「保存设置」同步登录。

Windows 免安装程序已重新构建。真实抖音链接的 exe 测试被自动审批以 `blocked by policy` 拦截，未提供更具体原因，故未声称通过该链接的 exe 下载验收。后续 1.1.1 exe 已实际通过全新临时浏览器资料的本机登录自检，以及 6 秒本机合成视频的完整下载和 0–4 秒 MP3 导出；核对了 exe 与 GitHub 发布包一致。这些本机检查不替代真实抖音链接验收。源码验收摘要见 `douyin-browser-results.json`。

普通 HTTP 请求可能只返回验证页面、带水印下载地址或配乐信息；现在抖音推荐登录模式会继续使用正常浏览器页面响应。只读取请求作品的详情数据，下载复用这次页面的 Cookie 属性与 User-Agent。已有独立浏览器只借用新建的后台标签，结束时清理本次标签；未运行时启动无界面辅助进程。不会自动处理登录、验证码或网站权限。

本次真实验收是一个视频链接，不代表所有抖音作品、图集或其他平台均已通过。小红书仍需后续真实账号验收。

## 交付与边界

免安装目录附带 FFmpeg / FFprobe、动态 Qt 库、第三方许可证和应用源码。当前裁剪先下载全源再导出，不节省完整源文件的下载流量。受平台频控、登录状态和解析器版本影响，不能承诺每条链接均成功。未标记水印的源也可能含原片标识。

构建时发现宿主 PATH 的 Poppler ICU 被误收入发行包，与 Qt 6.12 所需 Windows 系统 ICU 的导出函数不兼容。已在 `.spec` 中排除额外 ICU，保留 Windows 系统加载路径；修复后的独立 exe 已实际启动并成功解析同一 B站链接。

发行包 `_internal/assets/ffmpeg` 下的 FFmpeg / FFprobe 已用绝对路径独立运行，通过 0.4 秒合成视频的编码与探测检查，不依赖 PATH 中的 FFmpeg。后续发行版桌面自动化遇到 `window bounds changed; call get_window_state before using this window`，刷新后的重试仍失败，已停止进一步 UI 输入；发行版未额外声称完成新的端到端下载测试。源码版的真实视频 / 音频下载与发行版启动、解析、内置媒体工具均已分别验收。
